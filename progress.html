Architect report: bootstrap (T-000) done

architect · opus · 2026-11-07

Defined the system, stack, data model, API contract, local and AWS layout, and split the manager view into four buildable tickets. No application code was written; implementers build from these documents.

Documents produced
  • ARCHITECTURE.md 199 lines. The system's memory: overview, components, verified versions, data model, API conventions, patterns, personas and permissions, auth, AWS layout, local run, key decisions, dependency deferrals.
  • specs/T-000-bootstrap.md Repo layout, versions, Makefile targets, local environment, API contract workflow, cross-cutting concerns, testing strategy, Terraform module plan, implementation tickets.
  • specs/T-001-manager-view.md Feature spec: data model with columns, mock data volumes, API, backend rules, shared code, web screens and states, test notes, assumptions A1 to A9.
  • api/openapi.yaml 761 lines, OpenAPI 3.1. Passes redocly lint (one warning: /health has no 4xx response). A TypeScript client was generated from it as a check.
  • tickets/T-001a to T-001d Four implementation tickets in Given/When/Then, ordered and independently verifiable.
Key decisions
  • Terraform over CDK. Reviewable plan diffs for humans and the code-review agent, no synth step, mature AWS provider, S3 native state locking. IaC is specified only; not written in Phase 1.
  • Contract first. Hand-written OpenAPI 3.1 is the single source of truth. The backend is tested against it and the TypeScript client is generated from it, with a drift check that fails the lint if they disagree.
  • Auth (Phase 1). Seeded users, argon2id password hashes, HS256 JWT valid for 30 minutes, no refresh token. Role is reloaded from the database on every request. Painter gets 403 on manager endpoints, no token gets 401.
  • Monorepo. npm workspaces for shared, web and e2e; backend managed by uv; Makefile and scripts/dev.sh as entry points. Generated client code is committed.
  • Local and cloud parity. docker compose runs db, migrate, seed, backend and web (nginx) with one command. A no-Docker path (scripts/dev.sh) exists for this workspace. Web config.js is generated at container start from API_BASE_URL.
  • AWS layout. VPC over 2 AZs, ECS Fargate behind an ALB, RDS Postgres 16 in private subnets, S3 plus CloudFront for the web build, Secrets Manager, GitHub OIDC roles for CI/CD, migrations as a one-off ECS task before each deploy.
  • Photos. Generated SVG placeholders served through short-lived signed URLs. This matches the later S3 presigned-URL shape, needs no image dependencies and works offline.
  • Sync SQLAlchemy with psycopg 3. Read-only and low traffic, so sync is simpler to test.
  • Plain CSS, system fonts, no UI kit. Keeps the app small and fully offline.
  • CORS allowlist instead of a same-origin proxy. Mirrors production, where CloudFront and the API are on different domains.
  • Derived invoice status. Overdue and part-paid are computed by one pure function (void, draft, paid, overdue, part-paid, sent), so they always match payments and today's date.
  • Injectable clock. FIXED_NOW (non-production only) makes 'this month' figures deterministic in tests.

Assumptions (product owner may revise)
  • A1 All 60 seeded jobs are completed and each has one completion report.
  • A2 'Status' filtering covers review status and billing status, with separate filters.
  • A3 'This month' is the current calendar month in Europe/London. Outstanding is the unpaid balance of issued, non-void invoices; overdue includes part-paid.
  • A4 20% VAT. Payment terms 14 days for homeowners and 30 days for landlords and businesses. A paid deposit is deducted on the invoice.
  • A5 Billing 'amount' is the invoice total after deposit; 'paid' is payments against the invoice; deposits show on the report detail.
  • A6 Roles are exclusive; a painter signing in to the web app sees a 'managers only' page.
  • A7 Mock region is Bristol and Bath. Seed dates are relative to the seed date so current-month figures always exist.
  • A8 'Awaiting review' means not yet reviewed by a manager; Phase 1 has no review action.
  • A9 Sessions last 30 minutes with no refresh.

Security decisions recorded
  • Secret guard. When APP_ENV is not local or test, JWT_SECRET and PHOTO_URL_SECRET must be set explicitly. They are rejected if they are dev defaults, start with dev-only- (any case), have surrounding whitespace, or are equal to each other (ignoring case). Production also refuses demo accounts and FIXED_NOW.
  • APP_ENV. Required, with no default; must be exactly local, test, staging or production.
  • Seed guard. The seed runs only when APP_ENV is local or test, so staging has no demo data. A staging demo dataset needs an explicit decision.
  • NUL characters. Rejected with 422 in the login fields and the q search parameter.
  • safeRedirect. Only same-origin paths are accepted. Control characters, backslashes, // and /login targets are refused.
  • CSP. Generated by web/nginx/40-jobproof-config.sh, with strict API_BASE_URL host rules. Covered by the config-script unit test and e2e/tests/csp.spec.ts.
  • Demo accounts endpoint. Returns 404 unless DEMO_ACCOUNTS_ENABLED is set. The config refuses it when APP_ENV is production.
