# Spec T-002c: Admin sets the company name; header, tab title and login show it

Ticket: [tickets/T-002c-admin-sets-company-name.md](../tickets/T-002c-admin-sets-company-name.md).
Package 1 ([work packages](T-002-work-packages.md)). Depends on T-002a, T-002b.

## Questions and assumptions

- A1. Tab title format is "Page | Company" (default accepted). Before branding loads, or if it
  fails, the title is just "Page".
- A2. No "JobProof" anywhere in the UI: this ticket removes it from the header, login,
  full-page loading/error headings, `index.html` and the config-error screen.
- A3. "Control character" means Unicode category Cc (U+0000 to U+001F, U+007F to U+009F).
- A4. Length is counted in Unicode code points after trimming (Python `len`, JS
  `Array.from(s).length`).

## Summary

`PATCH /api/v1/admin/settings` for the company name; a shared branding hook with a sensible cache;
a `BrandingProvider` that feeds the header, login heading and every tab title.

## Patterns

None new. The branding cache is a plain module (see Web). Validation is a pure function shared
in spirit by backend (Pydantic validator) and shared TS (`companyName.ts`), the same "rule twice,
tested against the same cases" approach as billing status.

## Data

No schema change. `updated_at = now()` (app clock), `updated_by_id`, `updated_by_name` set on a
real change only.

## API

`PATCH /api/v1/admin/settings` (`updateAdminSettings`), admin only.
- Body `AdminSettingsUpdate` (`extra="forbid"`, at least one property): `company_name` string.
  (`theme` arrives in T-002e; until then, sending `theme` is 422 `extra_forbidden`.)
- 200 `AdminSettings`. No-op (trimmed name equals current) returns 200 unchanged with no write.
- 422 `validation_error`, `errors[].loc = ["body","company_name"]`, messages:
  "Enter a company name." (empty or spaces), "Use 60 characters or fewer.",
  "Remove control characters." (any Cc including NUL).
- 401 / 403 as the admin router.

## Backend

- `schemas/settings.py`: `AdminSettingsUpdate` with a `field_validator("company_name")` that
  trims, then applies the three rules in that order (first failure wins, one message).
- `services/settings.py`: `update_settings(session, user, update, now) -> AdminSettings`:
  `SELECT ... FOR UPDATE` the row, compute changed fields, return early if none, else set values
  and `updated_*`, commit. Returns the changed-field list for T-002f to audit (design the return
  value now: `list[tuple[field, old, new]]`).
- Route on `routers/admin.py`.

## Shared

- `shared/src/branding/companyName.ts`: `validateCompanyName(raw) -> {value} | {error}` with the
  same three messages and trimming; table-driven tests matching the backend cases.
- `shared/src/hooks/useBranding.ts`:
  - `useBranding()`: `useQuery({ queryKey: queryKeys.branding /* ["branding"] */, queryFn:
    getBranding, staleTime: 5 * 60_000, refetchOnWindowFocus: true, retry: shouldRetry,
    initialData: options.initial, initialDataUpdatedAt: 0 })`. `initialDataUpdatedAt: 0`
    marks a cached snapshot as stale, so it is shown at once **and** revalidated immediately.
  - Takes an optional `{ initial?: Branding }` so each platform supplies its own snapshot
    (web: localStorage; mobile: AsyncStorage later). No storage access in shared.
- `shared/src/hooks/useAdmin.ts`: `useUpdateAdminSettings()` mutation; on success
  `setQueryData(queryKeys.adminSettings, data)` and `setQueryData(queryKeys.branding,
  {company_name, theme})`, so the admin sees the change at once without a reload.

## Web

**Branding cache (`web/src/theme/brandingCache.ts`)**: `readSnapshot(): Branding | undefined`
and `writeSnapshot(b)`, key `jobproof.branding.v1` in `localStorage`. Every access in try/catch
(private mode, quota). A snapshot is used only if it passes validation (name 1 to 60 chars, no
Cc; five `^#[0-9A-F]{6}$` colours); anything else is ignored and removed. The snapshot is
per origin, which is per deployment (D1), so it can only ever hold this company's name.

Caching policy, end to end:
1. Server: `Cache-Control: no-cache` (browser may store, must revalidate). No CDN in front of
   the API in AWS (ALB), so no shared cache.
2. First visit, no snapshot: brand area empty (no text, fixed height so nothing jumps), title is
   just the page name, until `/branding` answers (scenario 3).
3. Later visits: the snapshot paints immediately (no colour or name flash) and is revalidated at
   once; the fresh value replaces it and is written back.
4. Long-lived tab: refetch on window focus after 5 minutes, so an Admin change reaches open tabs
   without a reload.
5. Failure: keep the snapshot if any, else empty brand and default theme (T-002d). Sign-in works.

**`web/src/theme/BrandingProvider.tsx`**: wraps the router in `App.tsx`; calls
`useBranding({ initial: readSnapshot() })`; writes the snapshot on success; exposes
`useCompanyName(): string | undefined` via context.

**Titles**: `useDocumentTitle(page)` in `components/ui.tsx` becomes
`document.title = name ? \`${page} | ${name}\` : page`. Page names: "Sign in", "Dashboard",
"Reports", "Report JP-1042" (the job reference), "Billing", "Settings", "Not authorised",
"Page not found", "Loading". Assign with `document.title` only (text, never HTML).

**Header (`Shell.tsx`)**: remove `BrandMark` and the "JobProof" text and `aria-label`; brand
link text is the company name (`<span class="brand-name">{name}</span>`), `aria-label` omitted
(the text is the label). While loading: an empty `brand-name` with `min-width: 8rem` and
`aria-hidden`.

**Login (`Login.tsx`)**: `<h1>` is the company name when known, else "Sign in" (scenario 4);
there is no flash of another name because no other name exists in the bundle (A2, T-002a
scenario 5). While the first load is pending and there is no snapshot, the heading is an empty
skeleton line, then the name or (on error) "Sign in".

**Other "JobProof" text**: `guards.tsx` sr-only `<h1>` becomes "Loading"/"Something went
wrong"; `main.tsx` config-error heading "Configuration error"; `index.html` `<title>Loading</title>`.

**Settings page (`pages/settings/CompanyNameForm.tsx`)**: label "Company name", input
`maxLength` not set (the validator explains), live validation with the shared function,
character count "12 / 60". Save disabled while unchanged (after trimming) or invalid. Saving:
button "Saving..." and disabled. Success: `role="status"` "Settings saved", and the "Last
changed by Tom Ashworth on 15 Oct 2026, 11:42" line updates. 422: show the server message
beside the field. 500 / network: `role="alert"` error with "Try again", typed value kept.

All name rendering is JSX text (React escapes it); never `dangerouslySetInnerHTML` (lint rule
`react/no-danger` is not configured; the reviewer checks, and scenario 6 tests it).
