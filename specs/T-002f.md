# Spec T-002f: Audit trail and the History panel

Ticket: [tickets/T-002f-audit-trail.md](../tickets/T-002f-audit-trail.md).
Package 2 ([work packages](T-002-work-packages.md)). Depends on T-002c, T-002e (settings
changes), T-002g (review). T-002i adds edit events.

## Questions and assumptions

- A1. Events are kept **indefinitely** (no retention job, no delete path).
- A2. No Admin history screen; the admin-only history endpoint exists so the data is reachable
  and its authorisation is tested (scenario 2).
- A3. The History panel shows the latest 100 events; with more it says "Showing the latest 100
  of {total} changes." (no paging UI; a report will rarely approach this).
- A4. Times shown in Europe/London "15 Oct 2026, 11:42".

## Summary

An append-only `audit_events` table enforced by the database, one `record_event` service used
in the same transaction as each change, two history endpoints and a History panel on the report.

## Patterns

- None from GoF. Events are written by an explicit call in each write service (not ORM event
  listeners): explicit calls keep "who, what, old, new" visible in the code that makes the change
  and make "failed actions leave no trace" automatic (same transaction).

## Data

Migration `0005_audit_events` (down_revision `0004`).

Enums: `audit_action` (`report.reviewed`, `report.reopened`, `report.edited`,
`settings.changed`); `audit_entity` (`report`, `settings`). Python: `AuditAction` StrEnum with
member names `report_reviewed` etc. and dotted values (`pg_enum` stores values).

**audit_events**
| column | type | notes |
|---|---|---|
| id | uuid pk default gen_random_uuid() | |
| seq | bigint generated always as identity, unique | tie-break for ordering within one transaction |
| occurred_at | timestamptz not null | the app clock's `now` passed by the caller (equals `reviewed_at` for a review) |
| actor_id | uuid not null, FK users `ON DELETE RESTRICT` | |
| actor_name | text not null | name snapshot (scenario 6) |
| action | audit_action not null | |
| entity_type | audit_entity not null | |
| report_id | uuid null, FK job_reports `ON DELETE RESTRICT` | `CHECK ((entity_type = 'report') = (report_id IS NOT NULL))` |
| request_id | text null | from `request_id_var`; stored, not returned |
| changes | jsonb not null default '[]' | list of `{field, item_id, item_label, old_value, new_value}`; `CHECK (jsonb_typeof(changes) = 'array')` |

Index `ix_audit_events_report_id_seq` on `(report_id, seq DESC)`; partial index
`ix_audit_events_settings_seq` on `(seq DESC) WHERE entity_type = 'settings'`.

**Append-only enforcement (scenario 5)**, created by the migration:
- Function `audit_events_append_only()` that `RAISE EXCEPTION 'audit_events is append-only'
  USING ERRCODE = '42501'` (insufficient_privilege).
- `BEFORE UPDATE OR DELETE ON audit_events FOR EACH ROW EXECUTE FUNCTION
  audit_events_append_only()`.
- `BEFORE TRUNCATE ON audit_events FOR EACH STATEMENT` executing a second function that raises
  the same error **unless** `current_setting('jobproof.allow_audit_truncate', true) = 'on'`.
- Triggers apply to every role, including the table owner, so they hold locally where the app
  and migrations share one database user. In AWS (planned, ARCHITECTURE.md §10) the app also
  connects as a separate role with only `SELECT, INSERT` on `audit_events`; the trigger remains
  as defence in depth.
- Downgrade: drop triggers, functions, table, enums.

**Seed**: `seed/loader.py` runs `SET LOCAL jobproof.allow_audit_truncate = 'on'` in its
transaction before the `TRUNCATE ... CASCADE` (truncating `users`/`job_reports` cascades to
`audit_events`). The seed is already refused outside local/test, so production can never set it
through the seed. The `reseed` test fixture uses the loader, so it works too.

Change records. Values are JSON strings, booleans or null:
| action | changes |
|---|---|
| report.reviewed | `[{field: review_status, old: "awaiting_review", new: "reviewed"}]` |
| report.reopened | `review_status reviewed→awaiting_review`, `reviewed_by "<name>"→null`, `reviewed_at "<ISO UTC>"→null` (the stored `old_value` of reviewed_by also keeps the id in an extra key `old_id`, not exposed) |
| report.edited | one entry per changed field: `painter_notes`, `manager_notes` (text), `checklist_done` (bool, with `item_id` and `item_label`), `checklist_note` (text, with item) |
| settings.changed | `company_name`, `theme_primary`, `theme_accent` |
`item_id`/`item_label` are null for non-checklist fields. Full values are stored (no truncation).

## API

| Operation | Personas | Notes |
|---|---|---|
| `GET /api/v1/manager/reports/{report_id}/history` (`listManagerReportHistory`) | manager | 200 `AuditHistory {items (<=100, newest first), total}`; 404 unknown id; 422 non-uuid |
| `GET /api/v1/admin/settings/history` (`listAdminSettingsHistory`) | admin | same shape, `entity_type = settings` |

Both 401 without a valid token, 403 for other roles (admin router / manager router guards).
Order: `seq DESC`. No endpoint updates or deletes events.

## Backend

- `models/audit.py`: `AuditEvent` (no `TimestampMixin`; `occurred_at` only).
- `services/audit.py`:
  - `record_event(session, *, actor: User, action, report_id=None, changes, now)`: adds the row
    to the session (no commit; the caller commits). `actor_name = actor.full_name` at that
    moment; `request_id` from `app.logging.request_id_var`. Refuses an empty `changes` list
    (programming error): callers must not record no-op events.
  - `report_history(session, report_id) -> AuditHistory`: 404 if the report does not exist,
    else two queries (count, latest 100).
  - `settings_history(session)`.
- Wire-up (each in the same transaction as the change):
  - `services/review.py` (T-002g step 5): `report.reviewed`.
  - `services/settings.py` (T-002c/e): `settings.changed` with the changed-field list; nothing
    when the list is empty (scenario 2 "a save that changes nothing records no event").
- `routers/manager.py` and `routers/admin.py`: the two GET routes.

## Shared

- Query key `reportHistory(id) = ["report-history", id]`; `useReportHistory(id)` with
  `retry: shouldRetry`. `useReviewReport` and (T-002i) `useUpdateReport` invalidate it.
- `shared/src/history.ts`: `describeEvent(event): {sentence, changes: {label, old, new}[]}`:
  - reviewed: "Priya Nair marked the report as reviewed"
  - reopened: "Report returned to Awaiting review (previously reviewed by Sarah Whitfield on 12
    Oct 2026, 09:15)"
  - edited: "Priya Nair changed Painter notes, Checklist: Skirting boards gloss" (field labels
    from `labels.ts`: `painter_notes` "Painter notes" (renamed "Operative notes" in T-002l),
    `manager_notes` "Manager notes", checklist "Checklist: {item_label}")
  - settings: "Tom Ashworth changed Company name, Primary colour"
  - Booleans render "Done"/"Not done"; null renders "(empty)".
  - `truncate(value, 200)` returns `{short, isTruncated}`.

## Web

`web/src/pages/report/HistoryPanel.tsx`, a "History" section at the bottom of
`ReportDetail.tsx` with its own query (independent of the report query: scenario 8).
- List newest first: time (London), then the sentence; under it, for each change, "Before" and
  "After" values as preformatted plain text (`white-space: pre-wrap`), cut at 200 characters with
  a "Show full change" toggle button (`aria-expanded`).
- Empty: "No changes recorded yet."
- Loading: skeleton; error: `ErrorState` with "Try again"; the rest of the page unaffected.
- More than 100: the A3 note.
