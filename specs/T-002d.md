# Spec T-002d: Default theme applied across the web app

Ticket: [tickets/T-002d-default-theme.md](../tickets/T-002d-default-theme.md).
Package 1 ([work packages](T-002-work-packages.md)). Decision D6. Depends on T-002a, T-002b
(and T-002c's `BrandingProvider`).

## Questions and assumptions

- A1. Screenshot approval: the test engineer attaches screenshots (login, dashboard, report,
  settings at 1280px and 360px) to the report; a visual miss does not block merging.
- A2. Look: formal, modern, minimal (Amazon/eBay-like, simpler): dark green header bar, white
  page, one green for primary actions, accent green for links and focus, thin grey rules, system
  fonts only, no gradients, no serif headings, no decorative colour blocks.

## Summary

Replace the Phase 1 palette with theme tokens driven by one theme object, applied at runtime from
`/branding` through the CSSOM, so T-002e can change it without a rebuild and the strict CSP holds.

## Patterns

None. One pure function (`applyTheme`) and CSS custom properties.

## Data / API / Backend

None (uses `GET /branding` from T-002a).

## Theming mechanism (CSP-compatible)

The CSP is `default-src 'self'` with no `style-src` override, so **inline `<style>` blocks and
`style="..."` attributes in markup are blocked**. Changing styles through the CSSOM is not
governed by CSP. Therefore:

- `web/src/theme/applyTheme.ts`: `applyTheme(theme: Theme, root = document.documentElement)`
  validates each value against `^#[0-9A-F]{6}$` (invalid values are ignored and the default for
  that token is used) and calls `root.style.setProperty("--jp-primary", theme.primary)` and the
  same for `--jp-accent`, `--jp-bg`, `--jp-surface`, `--jp-text`. Nothing else ever writes
  styles. No `<style>` element is created, no `insertRule`, no `style` attribute string.
- `main.tsx` calls `applyTheme(readSnapshot()?.theme ?? DEFAULT_THEME)` **before** the first
  render, so the first paint is themed (the HTML body is empty until React renders, so browser
  defaults never show).
- `BrandingProvider` calls `applyTheme` whenever the branding data changes (and on error leaves
  the current values, which are the snapshot or the defaults: scenario 4).
- The CSS (`web/src/styles/app.css`) only **references** `var(--jp-*)`; it contains no brand hex
  codes and no fallbacks with hex codes. Derived shades use `color-mix(in srgb, var(--jp-primary)
  85%, black)` (hover) and `color-mix(in srgb, var(--jp-primary) 55%, white)` (disabled). Use the
  keywords `white` and `black` outside the token blocks, never hex, so the scan in scenario 3
  stays simple.
- React's `style={{...}}` prop (used for swatches and the preview) also goes through the CSSOM
  and is allowed.

## Shared

- `shared/src/branding/defaults.ts` (T-002a) holds `DEFAULT_THEME`.
- `shared/src/branding/contrast.ts`: `relativeLuminance(hex)` (WCAG 2.2: sRGB channel
  `c <= 0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4`, `L = 0.2126R + 0.7152G + 0.0722B`),
  `contrastRatio(a, b) = (L1 + 0.05) / (L2 + 0.05)`, `meetsAA(ratio) = ratio >= 4.5` (unrounded),
  `formatRatio(ratio)`: 2 decimals half-up, except a failing ratio that would round to 4.50 is
  shown as 4.49. Used by T-002d tests and T-002e UI. Backend twin in T-002e.

## Web

Token set in `app.css` `:root` (three named groups, each with a comment):
1. **Brand (runtime, no values in CSS)**: `--jp-primary`, `--jp-accent`, `--jp-bg`,
   `--jp-surface`, `--jp-text`. On-primary text is always `white` (guaranteed >= 4.5:1 by D6).
2. **Neutral (fixed)**: `--muted: #5A635D` (6.22:1 on white, 5.75:1 on surface),
   `--line: #DDE3DC` (decorative rules), `--control-border: #7D877F` (3.72:1 on white, 3.44:1 on
   surface; WCAG 1.4.11 needs 3:1).
3. **Status (fixed, not brandable)**: the existing badge, alert, notice, checklist and stage
   colours renamed `--status-*` (amber, green, neutral, slate, blue, violet, red), each text
   colour >= 4.5:1 on its own background (unit tested). The badge text colours are the existing
   Phase 1 values; any pair below 4.5:1 is darkened in this ticket.

Usage:
- Page: `body { background: var(--jp-bg); color: var(--jp-text); }`.
- Header bar: background `var(--jp-primary)`, text and nav links `white`; active nav item a 3px
  white bottom border; header focus ring `white` (>= 3:1 on primary because primary >= 4.5:1 vs
  white). Remove the accent bottom border and the brand mark.
- Primary button: background `var(--jp-primary)`, text `white`; hover the 85% mix; disabled the
  55% mix with `white` text (disabled controls are exempt from contrast).
- Secondary button: white background, `--control-border` border, `--jp-text` text.
- Links, active pagination, focus ring everywhere outside the header: `var(--jp-accent)`;
  `:focus-visible { outline: 3px solid var(--jp-accent); outline-offset: 2px; }`.
- Cards and table stripes: `var(--jp-surface)`; panels have a 1px `--line` border, radius 6px,
  no shadows. Stat cards lose their multi-colour top borders.
- Typography: one system font stack for everything (remove `--serif`); headings 600 weight.
- Header at 360px: brand name truncates with ellipsis (`min-width: 0`), nav wraps to a second
  row, user name hides below 480px (Sign out stays). No horizontal overflow.

Other stray colours: delete `web/public/favicon.svg` and set `<link rel="icon" href="data:,">`
in `index.html` (stops the browser fetching `/favicon.ico`; `data:` is allowed by `img-src`, and
the bundle check only flags http(s) URLs). Login page background becomes plain `var(--jp-bg)`
(no gradient).
