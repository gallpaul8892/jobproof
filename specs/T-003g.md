# Spec T-003g: Photo upload (resumable) and sync status

Ticket: [tickets/T-003g-photo-upload-and-sync-status.md](../tickets/T-003g-photo-upload-and-sync-status.md).
Package D. Design sections 3.4, 3.5, 5, 7 (0011). Kind: backend + local infra + infra delta,
then mobile, then web (photos display). NFR-1, 4, 5, 7.

## Questions and assumptions

- A1. Background: uploads continue while Android keeps the process; the WorkManager task
  (T-003i) covers the closed app every >= 15 min; otherwise "Open the app to finish sending"
  (ticket default).
- A2. NFR-5 is met by restarting only the interrupted photo (0.8 to 2 MB), never the report.
- A3. The server accepts JPEG and PNG only; the app converts HEIC (design section 5).

## Summary

Photo registration and file upload through the API into private object storage with full
validation; the app's upload queue, progress and status; real photos on the manager's report.

## Patterns

Strategy (existing `PhotoStore`): URLs for seeded placeholders (HMAC) or uploaded files
(presigned GET), chosen per photo by `registered_at`. New `ObjectStore` protocol (`put`,
`delete`, `presign_get`) with one implementation `S3ObjectStore` (boto3), exercised by moto in
tests, moto server in `dev.sh` and SeaweedFS in compose. A Protocol with one product is kept
because tests need to substitute it and the boundary is a network service.

## Data

Migration `0011_photo_evidence` (down_revision `0010`): `report_photos` columns as design
section 7; `caption` server default `''`; unique partial index `uq_report_photos_original`
`(report_id, original_sha256) WHERE original_sha256 IS NOT NULL`. Downgrade refuses if any row
has `registered_at` set.

## API

`registerOperativePhoto` (PUT metadata), `uploadOperativePhotoContent` (PUT raw body),
`deleteOperativePhoto`, and `OperativeReport.photos`. `location` in the registration is T-003k
(422 as an unknown key until then). Remove `T-003g` from `PENDING_TICKETS`.

## Backend

- `services/photo_upload.py`:
  - `register(session, user, job_id, photo_id, body, now)`: `ensure_draft` (T-003f); look up the
    id: absent → checks (item belongs to job, limits 60/12 over the report, duplicate
    `original_sha256` → 409 `duplicate_photo` with `existing_photo_id`) and insert
    (`registered_at = now`, `clock_offset_seconds = round((now - device_sent_at).total_seconds())`,
    `width/height` = upload dims, `position` = max + 1) → 201; present on this report → compare
    evidence fields (409 `photo_content_mismatch` if different), update `stage`,
    `checklist_item_id`, `caption` if the report is a draft (409 `report_submitted` if submitted
    and any of them differ) → 200; present on another report → 409 `photo_content_mismatch`.
  - `store_content(...)`: route is `async def`: check `Content-Length` (missing → 422, over
    `PHOTO_MAX_BYTES` 10,485,760 → 413) and read `request.stream()` into memory with the cap;
    then `run_in_threadpool` for: process-wide `BoundedSemaphore(PHOTO_UPLOAD_CONCURRENCY=4)`
    non-blocking acquire (else 503 `busy`, `Retry-After: 5`); lock the photo row; already
    received → same SHA 200 / different 409; content type and magic bytes (`FF D8 FF` /
    `89 50 4E 47 0D 0A 1A 0A`) else 415; SHA-256 equals `upload.sha256` else 422
    `checksum_mismatch`; Pillow open + `verify()` + reopen, `MAX_IMAGE_PIXELS = 50_000_000`,
    `DecompressionBombWarning` as error (413), dimensions equal registration else 415;
    `metadata.strip()` (no re-encode); thumbnail (`draft()` then `thumbnail((480, 480))`, JPEG
    q75); `put` full then thumb (keys in design 5, `ContentType`, SSE `AES256`); set
    `storage_key`, `thumb_storage_key`, `content_type`, `sha256`, `stored_sha256`,
    `upload_bytes`, `received_at = now`; commit. Late arrival after submission: audit
    `report.photo_received` (wired in T-003h; a no-op hook here).
  - `delete(...)`: draft only (409 `report_submitted`); absent → 204; delete the row (and its
    checklist link), commit, then best-effort `ObjectStore.delete` of both keys (failure logged
    with the photo id only).
- `photos/metadata.py`: JPEG segment walk up to SOS dropping APP1, APP13, COM; PNG chunk walk
  dropping `eXIf`, `tEXt`, `iTXt`, `zTXt`, `tIME`; refuses malformed structure (415).
- `photos/store.py`: `url_for` dispatch: `registered_at is None` → placeholder; else
  `presign_get(storage_key or thumb_storage_key, ttl)`.
- Settings: `PHOTO_BUCKET` (default `jobproof-local-photos` in local/test, required in
  staging/production), `PHOTO_S3_ENDPOINT_URL`, `PHOTO_S3_PUBLIC_ENDPOINT_URL`,
  `PHOTO_S3_ADDRESSING_STYLE` (`virtual` default, `path` locally), `AWS_REGION` (eu-west-2),
  `PHOTO_UPLOAD_CONCURRENCY`, `PHOTO_MAX_BYTES`. Guard: in staging/production the two endpoint
  settings and `AWS_ACCESS_KEY_ID` must be unset.
- Dependencies (`pyproject.toml`): `boto3==1.43.126` (or the latest at build time, exact pin),
  `pillow==13.0.0`; dev `moto[s3,server]==5.2.5`. Never log bodies, file names or coordinates.

## Web

Manager report detail now shows real JPEG thumbnails and full images from presigned URLs (the
existing gallery and refetch-on-expiry logic). Photos not yet received are not listed (T-003h
adds the "still to arrive" line). CSP: `web/nginx/40-jobproof-config.sh` reads `PHOTO_ORIGIN`
(default `http://localhost:8333`, validated with the same origin rules as `API_BASE_URL`) and
adds it to `img-src`; `csp-parity.test.ts` treats the photos origin as a parameter on both sides;
`config-script.test.ts` gains hostile `PHOTO_ORIGIN` cases; e2e CSP test still passes with a
real uploaded photo (fixture uploaded through the API in e2e global setup).

## Mobile

- Engine steps 3 and 4 (design 3.4): upload copy (`expo-image-manipulator`, 2560 px long edge,
  JPEG 0.8) created once and persisted with its SHA-256 (`expo-crypto`) and the original's
  SHA-256; register; upload with `File` upload task (`BINARY_CONTENT`, `PUT`, headers
  `Authorization`, `Content-Type`, `X-App-Version`, `onProgress`, `AbortSignal`, 120 s timeout);
  max 2 at once, oldest first; delete flow; stage/item/caption changes after send → re-register.
- Thumbnail badges: Waiting (clock), Sending 40%, Sent (tick), Will retry + reason ("No signal",
  "Office system problem"), Couldn't be sent + reason; icon + word, never colour alone.
- Job screen "9 of 12 photos sent" with a progress bar; My jobs "Photos sending" marker; header
  line (design 3.4); `app/(app)/sync.tsx` lists every unsent item by job with reasons and **Sync
  now**.
- Wi-Fi only setting (Settings, off by default): automatic uploads wait on cellular ("Waiting for
  Wi-Fi"); Sync now asks "Use mobile data this time?".

  Tag `TODO(pin)` as B3.

- INFRA delta (infra engineer): app task role `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject` on
  `arn:aws:s3:::<photos bucket>/reports/*`; env `PHOTO_BUCKET`, `AWS_REGION`; `csp.txt` →
  `csp.tftpl` with `${photos_origin}` (virtual-hosted regional origin) and the parity test
  updated; WAF exclusion of `SizeRestrictions_BODY` for the content path (design R9).
