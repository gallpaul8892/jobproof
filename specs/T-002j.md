# Spec T-002j: Edit a report in the web app (conflict handling)

Ticket: [tickets/T-002j-edit-report-ui.md](../tickets/T-002j-edit-report-ui.md).
Package 2, last ticket ([work packages](T-002-work-packages.md)). Depends on T-002i, T-002h.

## Questions and assumptions

- A1. One edit form for the whole report (painter notes, manager notes, checklist), one Save.
- A2. "Closes the tab" protection uses the browser's `beforeunload` prompt (text is the
  browser's own); in-app navigation uses react-router's `useBlocker` with an in-page dialog.

## Summary

Edit mode on the report page, saving through `useUpdateReport`, with a reopen warning, a conflict
view that keeps the manager's text, validation counters and unsaved-changes protection.

## Patterns

None. Form state is local React state initialised from the loaded `ReportDetail`; the diff is
`buildReportUpdate` (shared, T-002i).

None beyond T-002i.

## Web

`web/src/pages/report/EditReportForm.tsx` and `useUnsavedChangesGuard.ts`; `ReportDetail.tsx`
switches between view and edit mode.

- "Edit report" secondary button in the page header actions (manager only; the page is already
  manager-only).
- Reviewed report: on entering edit mode, a notice (`role="status"`): "This report has been
  reviewed. Saving changes will return it to Awaiting review."
- Edit mode: Painter notes (label becomes "Operative notes" in T-002l) and "Manager notes
  (internal)" become `<textarea>`s with counters "123 / 5,000"; each checklist item shows the
  label as text, a checkbox "Done" and a note input with counter "/ 500". Photos and other
  sections unchanged (no edit controls).
- Buttons "Save changes" (primary) and "Cancel". Save disabled while nothing changed
  (`buildReportUpdate` returns null) or any field exceeds its limit; the over-limit message sits
  beside the field ("Use 5,000 characters or fewer.") with `aria-invalid`.
- Cancel: no changes, leave edit mode; with changes, confirm "Discard your changes?".
- Save: "Saving..." disabled; body = `buildReportUpdate(original, form)` with
  `version: original.version`.
  - 200: leave edit mode, `role="status"` "Changes saved"; page shows the new values; history
    refetched (new entry at top); next save uses the new version (the query cache now holds it).
  - 409 `version_conflict`: stay in edit mode, typed values kept; alert "Sarah Whitfield changed
    this report at 11:40. Your changes were not saved." Beside each affected field, a box
    "Current saved value:" with `problem.current` values (plain text). "Reload latest" asks
    "Discard your edits and load the latest version?" then refetches and resets the form.
    Nothing is overwritten.
  - 422: show messages from `fieldErrors` beside fields (matched by `loc`), else a general alert.
  - 403 mid-session: alert "You no longer have permission to edit this report." Typed text kept.
  - 500 / network: alert with "Try again" that resubmits the same body and version. If the first
    request actually succeeded, the retry gets a 409 whose `last_changed_by` is the current user
    and whose `current` equals the typed values: treat as saved (no duplicate history: the
    server wrote one event).
- Unsaved changes guard: while the form is dirty, `useBlocker` intercepts in-app navigation
  (dialog "Leave without saving?") and a `beforeunload` listener is registered (removed when
  clean or unmounted).
- All text rendered as JSX text or textarea values; `pre-wrap` and `overflow-wrap: anywhere` so
  1,000+ character notes do not break 360px layouts.

CSS: append a `/* report edit */` block to `app.css` using existing tokens only.
