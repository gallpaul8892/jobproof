# Spec T-002g: Mark a report reviewed (API, versioning)

Ticket: [tickets/T-002g-review-api.md](../tickets/T-002g-review-api.md).
Package 2 ([work packages](T-002-work-packages.md)). Decisions D3, D5. Depends on T-002b (Priya).

## Questions and assumptions

- A1. All managers can review any report.
- A2. The audit event for a review (T-002f scenario 1) is written by T-002f, which plugs into
  the service function defined here (one call site, see Backend).
- A3. A stale version on an already-reviewed report is `version_conflict` (scenario 4), not
  `already_reviewed`; the 409 body carries the current review fields so the UI can still say
  "X already reviewed this report" (T-002h scenario 4).

## Summary

First write endpoint: `POST /manager/reports/{id}/review`, plus `version`, `last_changed_at` and
`last_changed_by` on reports for optimistic concurrency.

## Patterns

None new. Concurrency is a row lock (`SELECT ... FOR UPDATE`) plus a version compare inside one
transaction; simpler and more testable than `UPDATE ... WHERE version = :v` because the service
also needs the old values (for the audit and the 409 body).

## Data

Migration `0004_report_versioning` (down_revision `0003`), table `job_reports`:
| column | type | notes |
|---|---|---|
| version | integer not null default 1 | `CHECK (version >= 1)`; existing rows get 1 |
| last_changed_at | timestamptz null | set on every real change (review or edit) |
| last_changed_by_id | uuid null, FK users `ON DELETE RESTRICT` | |

`CHECK ((last_changed_at IS NULL) = (last_changed_by_id IS NULL))`. Downgrade drops the three
columns. (An FK into users is fine here: `job_reports` is itself truncated by the seed.) The
seed does not set them (defaults: version 1, nulls), so every seeded report is version 1.

## API

`POST /api/v1/manager/reports/{report_id}/review` (`reviewManagerReport`), manager only.
- Body `ReviewRequest {version: int >= 1}` (`extra="forbid"`; `strict` int so `"1"`, `1.5`,
  `true` are rejected): else 422, `loc` `["body","version"]`.
- Path id not a uuid: 422. Unknown id: 404 `not_found`.
- Version mismatch: 409 `version_conflict` with `current_version`, `last_changed_at`,
  `last_changed_by`, `review_status`, `reviewed_at`, `reviewed_by` (no `current`).
- Already reviewed (version matches): 409 `already_reviewed` with `current_version`,
  `reviewed_at`, `reviewed_by`, and `detail` "Already reviewed by Sarah Whitfield at
  2026-10-12T09:15:00Z."
- 200: the full `ReportDetail` (same builder as GET), now `review_status: reviewed`,
  `reviewed_by` caller, `reviewed_at` = app clock now (UTC), `version` + 1.

`GET /manager/reports/{id}` (`ReportDetail`) gains `version`, `last_changed_at`,
`last_changed_by` (required, nullable as in the contract).

## Backend

- `models/work.py`: the three columns on `JobReport` (+ `last_changed_by` relationship).
- `services/review.py`: `review_report(session, report_id, user, version, now) -> None`:
  1. `session.get(JobReport, id, with_for_update=True)`; None → 404.
  2. `report.version != version` → `ProblemError(409, "version_conflict",
     extensions=conflict_extensions(report))`.
  3. `report.review_status == reviewed` → `ProblemError(409, "already_reviewed", ...)`.
  4. Set `review_status`, `reviewed_at = now`, `reviewed_by_id`, `version += 1`,
     `last_changed_at = now`, `last_changed_by_id`.
  5. `record_event(...)` hook (no-op until T-002f; T-002f fills it in the same transaction).
  6. Commit; the router then returns `get_report_detail(...)`.
  `conflict_extensions(report)` lives in `services/review.py` and is reused by T-002i.
- `routers/manager.py`: the route; `now()` from `app.clock`.
- Transactions: the service commits once. On any `ProblemError` nothing has been committed and
  `get_session`'s `with factory() as session` closes the session, which rolls back the open
  transaction and releases the row lock. No change to `db.py`.

## Shared

- `shared/src/hooks/useReportWrites.ts`: `useReviewReport(id)` mutation calling
  `reviewManagerReport({path, body: {version}})`. On success: `setQueryData(report(id), data)`,
  invalidate `["dashboard"]` and `["reports"]` (prefix). The UI reads 409 details from
  `ApiError.problem` (added in T-002e).
- `shared/src/conflict.ts`: `parseConflict(error) -> {kind: "already_reviewed" | "stale",
  reviewedBy?, reviewedAt?, lastChangedBy?, lastChangedAt?} | null`. Rule: `already_reviewed`
  code, **or** `version_conflict` whose `review_status` is reviewed and `last_changed_at ==
  reviewed_at` (the latest change was a review), is "already_reviewed"; any other
  `version_conflict` is "stale".
