# Spec T-002h: Review a report in the web app

Ticket: [tickets/T-002h-review-ui.md](../tickets/T-002h-review-ui.md).
Package 2 ([work packages](T-002-work-packages.md)). Depends on T-002g.

## Questions and assumptions

- A1. No "Mark reviewed and open next" button (default: not now).
- A2. Times are shown in Europe/London as "15 Oct 2026, 11:42" (existing `formatDateTime`).

## Summary

A review panel in the report page's field-worker section with a "Mark as reviewed" button,
reviewed-by line, and handling for "someone else reviewed first", "report changed", failures
and double clicks.

## Patterns

None. A small state machine is kept inside one component with `useMutation` state; no State
pattern class is warranted for three states.

## Data / API / Backend

None beyond T-002g.

## Shared

`useReviewReport`, `parseConflict` (T-002g).

## Web

`web/src/pages/report/ReviewPanel.tsx`, rendered by `ReportDetail.tsx` in the section
currently titled "Painter" (renamed "Operative" in T-002l), replacing today's "Review" row.

- Awaiting: text "Awaiting review" and a primary button "Mark as reviewed".
- Reviewed: "Reviewed by {name} on {date, time}" and no button.
- A `role="status"` live region inside the panel announces "Marked as reviewed" or the conflict
  message (scenario 8). The badge in the page header (`ReviewBadge`) re-renders from the query.
- Click: button disabled immediately (`mutation.isPending` and a ref guard set synchronously in
  the click handler, so a double click sends one request: scenario 7); label "Marking as
  reviewed..." with `aria-busy`.
- Success: the mutation already put the new `ReportDetail` in the cache; panel shows reviewed.
- 409 `already_reviewed` or a conflict that `parseConflict` classes as already reviewed: if
  `reviewedBy.id` equals the signed-in user's id (a retry of a request that actually succeeded),
  treat as success silently; otherwise show "Sarah Whitfield already reviewed this report at
  11:40." and refetch the report (page shows reviewed state; scenario 4).
- 409 stale: notice "This report changed while you were looking at it. Reload to see the latest
  version before reviewing." with a "Reload report" button that refetches; nothing reviewed
  (scenario 5). The Mark button is hidden until reloaded.
- 500 / network: `role="alert"` "Could not mark as reviewed. Try again." with the button
  enabled again; retry uses the same version (a lost-but-succeeded first request becomes the
  "self" case above: no double review, scenario 6).
- 401 mid-session: existing global handler. 403: generic error text.

Lists and dashboard: invalidated by the mutation (T-002g), so navigating back shows the new state
(scenario 3).
