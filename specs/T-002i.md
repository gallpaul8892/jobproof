# Spec T-002i: Edit a report (API, concurrency, audit, reopen)

Ticket: [tickets/T-002i-edit-report-api.md](../tickets/T-002i-edit-report-api.md).
Package 2 ([work packages](T-002-work-packages.md)). Decisions D3, D4, D5. Depends on T-002f, T-002g.

## Questions and assumptions

- A1. Completion date is not editable (default).
- A2. Editing a reviewed report reopens it (D3, default).
- A3. Notes are stored exactly as sent (no trimming, so the field worker's words are kept), except
  that an empty or whitespace-only string is stored as null. Line breaks are kept.
- A4. Length limits count Unicode code points: notes 5,000, checklist note 500.
- A5. "Version changes" in scenario 8 means a client cannot set the version: `version` in the body
  is only the precondition; the server always sets the new version.

## Summary

`PATCH /api/v1/manager/reports/{id}` for `painter_notes`, `manager_notes` and checklist
`done`/`note`, atomic, version-checked, audited, reopening reviewed reports; new
`manager_notes` column.

## Patterns

None new. Field diffing is a small pure function (`diff_report(current, update) ->
list[Change]`) so no-op detection, the audit entries and the response all come from one place.

## Data

Migration `0006_manager_notes` (down_revision `0005`): `job_reports.manager_notes text null`.
Seed: `ReportRow.manager_notes = None` on every row (dataclass default), re-seeding identical.
No length CHECK in the database (the API enforces limits; future clients may have other rules).

## API

`PATCH /api/v1/manager/reports/{report_id}` (`updateManagerReport`), manager only.

Body `ReportUpdate` (Pydantic, `extra="forbid"` at every level):
- `version` int >= 1, required (strict).
- `painter_notes`, `manager_notes`: string or null, <= 5000 code points, no NUL.
- `checklist`: >= 1 items of `{id: uuid, done?: bool (strict), note?: string|null <= 500, no
  NUL}`, each item with at least one of `done`/`note`, ids unique within the body.
- At least one of the three editable keys: else 422 `loc ["body"]` "Send at least one field to
  change."
- Anything else (photos, review_status, reviewed_by, label, position, job, customer, unknown):
  422 `extra_forbidden` naming the key.
- Pydantic reports all problems at once (`errors` entry per problem: scenario 9).

Order of checks and outcomes:
1. Body validation → 422 (nothing loaded).
2. `SELECT ... FOR UPDATE` the report with its checklist items → 404 if missing.
3. Every checklist id must belong to this report → else 422 `loc ["body","checklist",i,"id"]`
   "Checklist item does not belong to this report." (nothing saved: scenario 8/11).
4. `version` mismatch → 409 `version_conflict` with the T-002g extensions **plus** `current`:
   the current values of exactly the fields the body tried to change (`painter_notes`,
   `manager_notes`, and the sent checklist items as `{id, done, note}`).
5. Diff. Empty diff → 200 with the current `ReportDetail`, same `version`, no write, no event,
   review state unchanged (scenario 5).
6. Apply changes; `version += 1`; `last_changed_at = now`; `last_changed_by_id = user`.
   `record_event(report.edited, changes)`.
7. If `review_status` was reviewed: set awaiting, clear `reviewed_at`/`reviewed_by_id`;
   `record_event(report.reopened, ...)` with the previous reviewer's name and time (recorded
   after the edit event, so it is newest). One version bump in total.
8. Commit; return `get_report_detail`.

200 response is `ReportDetail` (now with `manager_notes`).

## Backend

- `models/work.py`: `manager_notes`.
- `schemas/report_write.py`: `ReportUpdate`, `ChecklistItemUpdate`, with a shared
  `NoNul = Annotated[str, AfterValidator(reject_nul)]` and an `empty_to_none` normaliser (applied
  in the service so validation messages still refer to the raw input).
- `services/report_edit.py`: `update_report(session, report_id, user, update, now)` following the
  order above; uses `conflict_extensions` from `services/review.py` and `record_event`.
- `services/reports.py`: `ReportDetail.manager_notes`.
- `routers/manager.py`: the `patch` route.
- `manager_notes` is internal: it is only ever returned by manager endpoints. When the painter
  app arrives, its endpoints must not return it (note added to ARCHITECTURE.md §15).

## Shared

- `useUpdateReport(id)` mutation in `useReportWrites.ts`: on success `setQueryData(report(id))`,
  invalidate `reportHistory(id)`, `["dashboard"]`, `["reports"]`.
- `parseConflict` (T-002g) also returns `current` for PATCH conflicts.

  ReportUpdate | null` (only changed keys; null when nothing changed) and the limits
  `NOTES_MAX = 5000`, `CHECKLIST_NOTE_MAX = 500`. Used by web now, mobile later.
