# Spec T-003b: Operative sign-in, secure session and sign-out

Ticket: [tickets/T-003b-operative-sign-in.md](../tickets/T-003b-operative-sign-in.md).
Package A. Design section 4 (sessions), 3.7. Kind: backend + shared + mobile. Decisions P7, T3-4.

## Questions and assumptions

- A1. Session: 30 days idle, 90 days absolute (T3-4, Paul to confirm).
- A2. Deactivation has no UI (B13); the new CLI `deactivate-user` is the office's tool for now.
- A3. Scenarios 9 and 10 need unsent items, which exist from T-003e; here the sign-out dialog
  reads the count from the local DB (0 until T-003e) and is tested with fixture rows.

## Summary

Device sessions with rotating refresh tokens and server-side revocation; operative-only sign-in
on the app; secure storage; sign-out that never loses unsent work.

## Patterns

Strategy (existing `TokenStore`): `SecureTokenStore` over `expo-secure-store`. Single-flight
refresh inside the shared Adapter (a shared promise, not a pattern class).

## Data

Migration `0009_auth_sessions` (down_revision `0008`): table `auth_sessions` exactly as design
section 7. Downgrade drops it. Seed loader truncates it (it references users).

## API

`createDeviceSession`, `refreshDeviceSession`, `endDeviceSession` as in the contract. Codes:
`invalid_credentials` (401), `operatives_only` (403), `session_ended`, `account_inactive` (401).
Every authenticated operation: a token with `sid` whose session is revoked or past its absolute
expiry is 401 `session_ended`; an inactive user with a `sid` token is 401 `account_inactive`
(tokens without `sid` keep `unauthenticated`).

## Backend

- `services/sessions.py`: `create_session`, `refresh`, `revoke(session, reason)`,
  `revoke_all_for_user`. Token `"<uuid>.<secret>"`; `hashlib.sha256`; `hmac.compare_digest`.
  Row lock on refresh. Rules exactly as design section 4.
- `security.py`: `create_access_token(..., sid=None, ttl=...)`; `decode_access_token` returns
  `sid` when present.
- `deps.current_user`: session check when `sid` present (one PK lookup).
- `cli.py deactivate-user --email`: sets `is_active=false`, revokes sessions, prints the user id
  only.
- Settings: `DEVICE_ACCESS_TTL_SECONDS` (>= 60, default 900), `DEVICE_SESSION_IDLE_DAYS` (30),
  `DEVICE_SESSION_MAX_DAYS` (90), `REFRESH_REUSE_GRACE_SECONDS` (60).
- Logging: never log tokens or emails; log `session_id` and outcome only.

## Shared

`api/client.ts`: `refresh?: () => Promise<boolean>` option; on 401 (not `invalid_credentials`)
call it once per burst (shared promise), retry the call once; `onUnauthorized` only if refresh
returns false. Vitest: two concurrent 401s trigger one refresh; refresh failure calls
`onUnauthorized` once; web config (no refresh) unchanged.

## Web

None.

## Mobile

- `src/api/sessionManager.ts`: holds access token and expiry in memory; refresh token and
  `device_id` (random UUID on first launch) in SecureStore; proactive refresh 60 s before
  expiry; exposes `status` (`signed_out | signed_in | needs_sign_in | inactive`).
- `app/sign-in.tsx`: email (autofill `username`/`email`, `textContentType`, `autoComplete`),
  password with Show/Hide (autofill `password`), client validation "Enter your email." /
  "Enter your password." (no request), error mapping: 401 → "Email or password is incorrect."
  (email kept, password cleared); 403 `operatives_only` → "This app is for operatives. Managers
  use the web app." (nothing stored); network error → "No signal. Sign in needs a connection.";
  426 → update screen (T-003n).
- `Stack.Protected guard={signedIn}` for `(app)`; header shows the user's full name.
- Sign-out (Settings): count unsent items for this user (photos not `sent`, dirty drafts, queued
  submits); 0 → confirm, `DELETE /auth/sessions/current` (best effort), clear tokens, clear the
  query cache for the user, go to sign-in; > 0 → "N photos haven't reached the office yet. Stay
  signed in so they can send." with "Stay signed in" (default) / "Sign out anyway" (keeps the
  rows and files under the user id).
- Another user signs in: everything is keyed by `owner_user_id`; the engine runs only for the
  signed-in user.
- `account_inactive` anywhere → sign-in screen with "Your account is no longer active. Contact
  the office."; local items untouched.
