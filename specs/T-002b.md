## Questions and assumptions

- A2. Production Admin accounts are created by a documented command (below); no user management UI.

## Summary

Adds role `admin`, the admin router with `GET /api/v1/admin/settings`, two seed users (admin Tom
Ashworth, second manager Priya Nair), a `create-admin` command for real deployments, role-aware
web guards, navigation and landing pages, and a read-only Settings page.

## Patterns

- Authorisation stays **role-only** with `require_roles(...)` as a router-level dependency (no
  new pattern): admin rules are "admin only", manager rules "manager only". The Policy pattern
  noted in ARCHITECTURE.md §6 is still deferred to ownership rules (painter app).
- Web: one generic guard component `RequireRole` replaces `RequireManager` (same behaviour,
  role as a prop). Not a pattern; a parameter.

## Data

Migration `0003_admin_role` (down_revision `0002`):
- Upgrade: `ALTER TYPE user_role ADD VALUE IF NOT EXISTS 'admin'`. Postgres 16 allows this in a
  transaction as long as the new value is not used in the same transaction; the migration uses
  nothing else.
- Downgrade: refuse with a clear error if any `users.role = 'admin'` row exists (data loss
  otherwise). Else: rename `user_role` to `user_role_old`, create `user_role` (manager, painter),
  `ALTER TABLE users ALTER COLUMN role TYPE user_role USING role::text::user_role`, drop
  `user_role_old`. The migration round-trip test runs on an empty schema, so it passes.
- `backend/app/models/enums.py`: `UserRole.admin = "admin"`.

## API

| Operation | Personas | Responses |
|---|---|---|
| `GET /api/v1/admin/settings` (`getAdminSettings`) | admin | 200 `AdminSettings` `{company_name, theme, updated_at, updated_by}`; 401; 403 |
| `GET /api/v1/auth/me`, `POST /auth/login` | all roles | role may now be `admin` |
| `GET /api/v1/auth/demo-accounts` | as before | includes admin and both managers |
| every `/api/v1/manager/*` | manager only | admin gets 403 `forbidden` (scenario 4) |

`Role` enum is `manager | painter | admin`.

## Backend

- `backend/app/routers/admin.py`: `APIRouter(prefix="/api/v1/admin",
  dependencies=[Depends(require_roles(UserRole.admin))])`. Every admin route goes on this
  router, so no admin route can be added without the guard (same structure as manager).
- `GET /settings` returns `services.settings.get_admin_settings(session)`; `updated_by` is
  `PersonRef(id=updated_by_id, name=updated_by_name)` or null.
- `backend/app/cli.py`, run as `python -m app.cli create-admin --email EMAIL --full-name NAME`:
  - Password from env `ADMIN_INITIAL_PASSWORD` if set, else an interactive `getpass` prompt
    twice. Minimum 12 characters, maximum 200, no NUL. Never echoed or logged.
  - Email normalised like login (`normalise_email`); refuses if the email exists (exit 1).
  - Creates `role=admin`, `is_active=true`, argon2id hash. Logs one JSON line
    `{"event":"admin_created","user_id":...}` (no email, no password).
  - Works in every APP_ENV (it is not the seed). Documented in ARCHITECTURE.md §11 and the README.
  - AWS: run as a one-off ECS task with `ADMIN_INITIAL_PASSWORD` injected from a Secrets Manager
    secret that is deleted after first sign-in (infra phase).

## Web

- `web/src/app/roles.ts`: `homeFor(role)`: manager `/`, admin `/settings`, painter
  `/not-authorised`; `canVisit(role, pathname)`: manager for `/`, `/reports*`, `/billing`;
  admin for `/settings`.
- `web/src/app/guards.tsx`: `RequireRole({ role })` (logic of today's `RequireManager`, with
  `me.data.role !== role` sending to `/not-authorised`). Nothing under it mounts until
  `/auth/me` answers, so no `/manager/` or `/admin/` request is made by a wrong persona
  (scenario 7).
- `router.tsx`: manager group under `<RequireRole role="manager" />`, new group
  `<RequireRole role="admin" />` with `/settings`.
- Login (`Login.tsx`): after sign-in, go to `safeRedirect(from)` only if
  `canVisit(role, from)`, else `homeFor(role)`. Demo account role label uses `roleLabel`.
- `Shell.tsx`: navigation by role: manager Dashboard, Reports, Billing; admin Settings. Brand
  link goes to `homeFor(role)`. User name and Sign out unchanged.
- `NotAuthorised.tsx`: message per role: admin "You are signed in as {name}, an administrator.
  This page is for managers. Go to Settings." with a link to `/settings`; manager visiting
  `/settings`: "This page is for administrators." with a link to the dashboard; painter as today.
- `pages/Settings.tsx` (read-only in this ticket): heading "Settings"; section "Company" with the
  name; section "Colour scheme" with primary and accent swatches (`<span class="swatch">` whose
  background is set through the React `style` prop, which uses the CSSOM and is allowed by the
  CSP) and their hex codes as text. States: loading skeleton, error with "Try again"
  (`QueryBoundary`), never blank.
