# Spec T-003n: Error states and session expiry

Ticket: [tickets/T-003n-error-states-and-session-expiry.md](../tickets/T-003n-error-states-and-session-expiry.md).
Package E. Design sections 3.4 (classifier), 4, 10. Kind: small backend (426 gate) + mobile.
P7, Q1.

## Questions and assumptions

- A1. Only a hard minimum version is enforced; no "optional update" nagging (ticket default).
- A2. Remote wipe is out of scope; ending the session server-side is the control.
- A3. The server has no application rate limit; 429 can come from the WAF (prod) and is handled
  like 503.

## Summary

The minimum-supported-version gate (426), and complete, plain-English handling of every error
class without losing work: expired session, server down, update required, vanished job, closed
job, refused photo, rate limiting, crash.

## API

All operative and session operations answer 426 `app_update_required` when `X-App-Version` is
present and below `MOBILE_MIN_VERSION_ANDROID` (declared in the contract already). No contract
item is staged for this ticket.

## Backend

`app/versioning.py`: `parse_semver`, dependency `require_supported_app` added to the operative
router and the three session routes: header absent → allowed (web and tools); malformed → 422;
below minimum → 426 with detail "Please update the app to continue.". Setting validated at
startup.

## Mobile

- Session expiry (refresh `session_ended`): engine pauses for the user; banner "Please sign in
  again to finish sending." → sign-in with the email kept; after signing in as the same user the
  app returns to the previous route and the engine resumes (scenario 1, 2). Offline: no prompt
  until signal returns and a send is needed (3). A different user signing in leaves the first
  user's rows untouched and unsent (4).
- Server errors for a period: one line "The office system is having problems. Your work is saved
  and will send later." (5). 429/503: "Busy. Trying again shortly." with longer backoff (10).
- 426: full-screen "Please update the app to continue." with a button to the Play listing
  (`market://details?id=<package>`, falling back to the https URL); queue and drafts kept;
  `getAppStatus` re-checked on return (6).
- Job vanished (404 on any job request, or a job with local work missing from the list):
  "Needs attention" section on My jobs and the Sync screen with "This job was changed by the
  office. Contact the office." and Sync now; nothing deleted (7). Closed job (8), refused photo
  with Delete / Leave (9).
- Crash: an `ErrorBoundary` per route with "Something went wrong. Your work is saved." and Back;
  a `sync_meta` flag set at start and cleared on clean background tells the next launch to show
  "The app closed unexpectedly. Your work is saved." (11).
- Wording test: every user-facing error string comes from `src/features/errors/messages.ts`; a
  test asserts none contains digits like HTTP codes or the words "error code", "exception",
  "null" (12).
- Deactivated: T-003b (13).
