# Spec T-003h: Submit the completion report

Ticket: [tickets/T-003h-submit-completion-report.md](../tickets/T-003h-submit-completion-report.md).
Package D. Design sections 3.4, 6, 7 (0012), 8. Kind: backend, mobile, web. P1, P2, Q2, Q3, T3-2.

## Questions and assumptions

- A1. Submit with photos still sending is allowed (T3-2, Paul to confirm); the manager may still
  review, with a warning.
- A2. "After" is required for every job type in the pilot (ticket default).
- A3. `submitted_at` is the server's acceptance time; the phone's confirm time is
  `device_submitted_at` (shown to the manager when it differs by more than 5 minutes, T-003k).

## Summary

`POST /operative/jobs/{id}/report/submit` with server-side completeness rules, idempotent by
`submission_id`; the submit flow in the app; "Submitted by ..." and "N photos still to arrive" on
the manager's report.

## Patterns

Rule twin: the completeness rule exists once per side (`services/submission.py` and
`shared/src/operative/submitRules.ts`) with one case table `submitCases.json` read by pytest and
Vitest, as the customer validators do (T-002n). No new GoF pattern.

## Data

Migration `0012_report_submission` (down_revision `0011`): `job_reports.submission_id` uuid
unique null, `device_submitted_at` timestamptz null, `submit_clock_offset_seconds` int null;
`audit_action` gains `report.submitted`, `report.photo_received` (autocommit block, as 0007).
Downgrade refuses if such events exist.

## API

`submitOperativeReport`; `OperativeReport.submission_id`, `device_submitted_at`;
`ReportDetail.submitted_by`, `pending_photo_count`. Remove `T-003h` from `PENDING_TICKETS`.

## Backend

`services/submission.py` `submit(session, user, job_id, body, now)`, one transaction, job row
lock, order exactly as the contract:
1. Report submitted: same `submission_id` → 200 current job (no write); else 409
   `already_submitted` (`submitted_at`).
2. `job_cancelled` / `job_closed` (409).
3. `ensure_draft`; apply `draft` if sent (T-003f rules).
4. `photo_ids` minus registered ids → 409 `photos_not_registered` (`missing_photo_ids`).
5. Completeness over registered photos (received or not) and non-removed items → 422
   `submission_incomplete`; messages: "Add at least 1 Before photo.", "Add at least 1 After
   photo.", per item "Tick this item or say why it wasn't done."
6. Write: `state submitted`, `submitted_at = now`, `submitted_by_id`, `submission_id`,
   `device_submitted_at`, `submit_clock_offset_seconds = now - device_sent_at`,
   `review_status awaiting_review`; report items for any job items added since the draft; job
   `completed`, `completed_on = max(scheduled_start, london_date(now))`; audit
   `report.submitted` (actor = operative, entity report, no changes).
- The unique `submission_id` and the row lock make two concurrent submits produce one report
  (the second sees step 1).
- T-003g hook: a file arriving after submission records `report.photo_received`.
- Manager `ReportDetail`: `submitted_by` (seeded: painter), `pending_photo_count` (registered,
  not received). Dashboard counts gain the report at submit (existing queries, state filter).

## Shared

`operative/submitRules.ts` `submissionProblems({photos, checklist})` → list of problems with the
same wording; `submitCases.json`; `history.ts`: `report.submitted` → "{actor} submitted the
report", `report.photo_received` → "A photo from {actor} arrived after submission".

## Web

Report detail header: "Submitted by Dan Hughes at 14:12" (London time); when
`pending_photo_count > 0` a notice "2 photos still to arrive" and, beside Review, "2 photos have
not arrived yet. You can still mark it reviewed." History shows the two new sentences.

## Mobile

- Submit button on the job screen → `submit.tsx`: local check with `submissionProblems`;
  problems listed with actions ("Take After photo", tappable item names); else summary "2 Before,
  3 After, 1 During photos; 9 of 9 checklist items; notes added; customer sign-off: none"; with
  unsent photos the T3-2 choice "Wait" / "Submit now"; confirmation "Submit this report? You
  can't change it afterwards." with Cancel.
- Confirm: create and store `submission_id` and `device_submitted_at`, `local_state =
  'submit_queued'` in one transaction (design 3.4 step 5 sends it). Online result: "Report
  submitted" with the time; with photos pending: "Submitted. 2 photos still sending".
- After success: local draft read-only (`submitted`), job shows "Submitted", read-only view with
  "Contact the office to change this report." and "Submitted 14:12 today by Dan Hughes" /
  "Reviewed by Sarah Whitfield" (no manager notes, never returned).
- Errors: `job_cancelled`, `job_closed` ("The office has already closed this job."), others in
  plain words; draft unchanged and kept.
