# Spec T-003e: Capture photos (camera and gallery), saved on the phone

Ticket: [tickets/T-003e-capture-photos.md](../tickets/T-003e-capture-photos.md). Package C.
Design sections 3.3, 3.6. Kind: **mobile only** (no backend, contract or web change). P3, P5, P6.

## Questions and assumptions

- A1. Full camera resolution is kept on the phone; the upload copy is made later by the sync
  engine (T-003g). Orientation is recorded as the camera produced it, never rewritten.
- A2. "Safe once the shutter is pressed" means from the moment `takePictureAsync` resolves (the
  shutter sound and the thumbnail); a kill during the few hundred milliseconds of capture itself
  cannot be guaranteed by any app.
- A3. Location capture is T-003k; permissions UX is T-003l (this ticket uses a minimal camera
  permission request that T-003l replaces).
- A4. A photo taken for a job with no local draft creates the local draft row; the job shows "In
  progress" locally at once (the server learns at the first sync, T-003f/g).

## Summary

The local photo store: in-app camera, gallery import, the `photos` table and files, viewing,
caption, stage, deletion, limits and storage checks.

## Patterns

Adapter: `LocalDb` (interface `exec/run/get/all/transaction`) with `ExpoSqliteDb` (app) and
`NodeSqliteDb` (Jest, `node:sqlite`) so the same SQL is unit tested in Node. Adapter:
`PhotoFiles` over `expo-file-system` (`Paths.document`, `File.move`, `Paths.availableDiskSpace`)
with an in-memory fake. Real problem solved: there is no device in CI or the workspace.

## Data

Local SQLite only: migration v1 creates `drafts`, `checklist_states`, `photos`, `sync_meta` as in
design section 3.3 (all columns created now, used by later tickets). `PRAGMA journal_mode=WAL;
PRAGMA synchronous=FULL; PRAGMA foreign_keys=ON`.

## Mobile

- `camera.tsx`: `CameraView` full screen; three large stage buttons Before / During / After
  (last used preselected, stored in `sync_meta`); shutter (>= 72 dp); counter "5 photos"; the
  camera stays mounted between shots and saving runs off the UI path, so the next shot is ready
  at once (NFR-3). No flash/zoom beyond defaults.
- Save path (design 3.6): resolve → `File.move` into `photos/<userId>/<photoId>.jpg` → insert row
  (`sync_state = 'saved'`, `source = 'camera'`, `taken_at` = device now, `taken_at_source =
  'device_clock'`, original width/height/bytes) in one transaction → thumbnail appears.
- Startup recovery of orphan files (stage = last used, flag `recovered`).
- Gallery: `launchImageLibraryAsync({ mediaTypes: ['images'], allowsMultipleSelection: true,
  exif: true })` then choose the stage; each asset copied (not moved) into app storage; EXIF
  date per design 3.6 (`file_metadata` or `added_time`); unreadable items skipped with "1 file
  couldn't be added"; "4 photos added".
- Photo groups on the job screen (Before, During, After) with thumbnails and the local time
  ("08:14"); full-screen viewer with pinch zoom, stage, time, caption; **no** crop, rotate,
  filter or draw anywhere (P3). Stage change and caption edit allowed while the local draft is
  not submitted; caption over 140 → "Keep it to 140 characters." with the text kept.
- Delete: "Delete this photo? This can't be undone." → `deleted = 1` (the engine removes server
  copies in T-003g); files removed when no server copy exists.
- Limits: 60 per report and 12 per item counted from non-deleted rows: "This report has the
  maximum 60 photos." / "This item has the maximum 12 photos."; nothing added.
- Storage: banner "Phone storage is low." under 500 MB; under 100 MB capture refused with "Not
  enough space to save photos. Free up space on your phone."
- Never in the gallery (P6): only `CameraView` and app-private paths; no `MediaLibrary` import
  (lint rule bans `expo-media-library`).
- Photos belong to the job id in the row; screens query by `(owner_user_id, job_id)`.

## Infra / local

Config plugins: `expo-camera` with `recordAudioAndroid: false`; `expo-image-picker` with no
media-library permissions (photo picker). `android.blockedPermissions` per design section 12.
