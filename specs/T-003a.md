## Summary

Create the `mobile/` workspace on Expo SDK 58, wire the shared generated client, show the
company name and theme, handle an unreachable server, and add the public `GET /app/status`.

## Patterns

Existing Adapter (`configureApiClient`) reused; the two shared changes below keep it platform
neutral. No new pattern.

## Data

None.

## API

`GET /api/v1/app/status` (`getAppStatus`, public): `{server_time, api_version,
min_supported_versions: {android}}`, `Cache-Control: no-store`, no DB access.
`MOBILE_MIN_VERSION_ANDROID` (default `0.0.0`, semver validated at startup). Enforcement (426) is
T-003n.

## Backend

`app/routers/app_status.py`; `server_time` from `app.clock.now()` (so `FIXED_NOW` applies in
tests), `api_version` from the contract version constant. Remove `T-003a` from `PENDING_TICKETS`.

## Shared

1. **First step of the ticket**: `npm run gen` and commit `shared/src/generated/` (whole T-003
   contract). The new required properties of `ReportDetail`, `ReportPhoto` and `ChecklistItem`
   become required in the generated types, so typed web test fixtures fail to compile: add the
   fields (seed-like values: `submitted_by` = the painter, `pending_photo_count: 0`, nulls,
   `source: "camera"`, `cannot_do: false`, `removed: false`...) in the same commit, as T-002 did.
   The web does not display them until T-003g/h/k.
2. `api/client.ts`: fall back when `AbortSignal.any` or `AbortSignal.timeout` is missing
   (combine with a manual `AbortController`, clear the timer on settle). Vitest: delete the
   globals in a test and assert timeout and caller-abort still work.
3. React alignment (design R4): read the React 19.3.1 changelog; if it has no fix the web needs,
   pin `react`/`react-dom` 19.3.0 across the repo (web, shared dev deps, mobile) so npm hoists
   one copy; otherwise keep 19.3.1 for web and add a Metro `resolveRequest` that forces
   `react`, `react-native` and `@tanstack/react-query` to `mobile/node_modules`. Record the
   choice in ARCHITECTURE section 3. Shared `peerDependencies.react` becomes `^19.3.0`.

## Mobile

- `npx create-expo-app` template `default` for SDK 58 trimmed to the layout in design 3.1;
  TypeScript strict; ESLint with the repo config; `npx expo install` for every Expo package.
- `app.config.ts`: name, slug, `android.package`, `minSdkVersion 29` (via `expo-build-properties`),
  `allowBackup: false`, `extra.apiBaseUrl` from `process.env.API_BASE_URL` (required; build fails
  if missing), `extra.variant` from `APP_VARIANT`; cleartext HTTP only when `APP_VARIANT=development`.
  `.env.local` (uncommitted) for local dev; `mobile/.env.example` committed.
- `eas.json`: profiles `development`, `preview`, `screenshots`, `production` with `environment`
  set, no URLs.
- `src/config.ts` reads `Constants.expoConfig.extra`; `configureApiClient({ baseUrl })` at start.
- Root layout: QueryClient, `BrandingProvider` (shared `useBranding`, snapshot in
  `expo-sqlite/kv-store` key `jobproof.branding.v1`, validated with `contrast.ts` before use),
  placeholder sign-in screen with header: company name in white on `theme.primary`; no snapshot
  and no network → default theme and heading "Sign in" (scenario 3).
- Reachability: on launch `getAppStatus`; network error or timeout → full-screen "Can't reach the
  office system. Check your signal and try again." with Retry (scenario 7). Never blank.
- Wording: labels from shared; a Jest test scans `mobile/app` and `mobile/src` strings for
  "painter" (case-insensitive) and fails (scenario 8).
- Splash and icon: plain placeholder with the app name.

## Infra / local

fetch). No CI change yet beyond adding the workspace to `npm run lint`/`npm test` (the `mobile`
CI job is added in T-003b's PR by the infra engineer, design section 11).
