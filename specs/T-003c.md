# Spec T-003c: My jobs today

Ticket: [tickets/T-003c-my-jobs-today.md](../tickets/T-003c-my-jobs-today.md). Package B.
Design sections 6, 7 (migration 0010). Kind: backend (+ seed) then mobile. Q10, Q11.

## Questions and assumptions

- A1. Jobs have a date, not a time: "scheduled order" = open jobs first, then by `reference`
  (references follow `scheduled_start`).
- A2. A job completed by the office with no operative report shows "Completed by office", not
  startable (ticket default).
- A3. Cancelled jobs scheduled today are listed as "Cancelled"; earlier cancelled jobs are not.
- A4. The seeded "already submitted" job belongs to Priya Shah (so Dan's list in scenario 1 is
  exactly his 3 to-do jobs); Dan's draft (6 of 9) is scheduled yesterday (scenario 3 and 4).

## Summary

The operative work model (job checklists, report states) and the list endpoint, the seed for
"today", and the My jobs screen with offline cache.

## Patterns

None new. Ownership is one function `get_own_job` / one query filter (design section 6).

## Data

Migration `0010_operative_work_model` (down_revision `0009`), in this order:
1. `job_checklist_items` (`id` uuid PK, `job_id` FK jobs RESTRICT, `position` smallint,
   `label` text not null, `removed_at` timestamptz null, timestamps; unique `(job_id, position)`;
   index `job_id`).
2. Backfill: one job item per existing report item **with the same id**, `job_id` from the report.
3. FK `report_checklist_items.id → job_checklist_items.id` (RESTRICT);
   `report_checklist_items.cannot_do boolean not null default false`;
   `CHECK (NOT (done AND cannot_do))`.
4. `CREATE TYPE report_state AS ENUM ('draft','submitted')`; `job_reports.state report_state
   not null default 'submitted'`, then drop the default; `submitted_at`, `review_status` drop
   NOT NULL; `submitted_by_id` uuid FK users RESTRICT, backfilled from `painter_id`; index on
   `state`.
5. Checks: `(state = 'submitted') = (submitted_at IS NOT NULL AND submitted_by_id IS NOT NULL
   AND review_status IS NOT NULL)`; `state = 'submitted' OR (reviewed_at IS NULL AND
   reviewed_by_id IS NULL)` (a NULL `review_status` would otherwise slip through the existing
   review check).
Downgrade: refuse if any `state = 'draft'` or `cannot_do` row exists; else reverse.

## API

`GET /api/v1/operative/jobs` (`listOperativeJobs`) with the T-003c properties of `OperativeJob`
(`notes`, `contact`, `checklist`, `report` are T-003d). Remove `T-003c` from `PENDING_TICKETS`.

## Backend

- Models: `JobChecklistItem`, `Job.checklist_items`, `JobReport.state/submitted_by`, Optional
  types; fix every mypy error in manager services by filtering submitted reports.
- `services/reports.py` `submitted_reports()` (a `select` with `state = 'submitted'`) used by the
  report list, detail, review, edit, history, dashboard, invoices (`report_id` only if
  submitted) and customer impact. Draft id on any manager operation → 404.
- `services/operative_jobs.py`: `list_jobs(session, user, today)`; status mapping
  (`cancelled` > `submitted` > `completed_by_office` > `in_progress` > `to_do`);
  `checklist_total` = job items not removed; `checklist_dealt_with` from the report items
  (done, or `cannot_do` with a non-blank note). One query for jobs + `selectinload` of items and
  report; no N+1 (the existing performance-logging test bound applies).
- Router `routers/operative.py`, `require_roles(painter)`.
- Seed `seed/operative_day.py` (`build_operative_day(anchor)`, deterministic, appended to the
  dataset): Dan: today "Repaint lounge, hall and landing" BS6 5QA (9 items, notes incl. "Key safe
  by the front door; code sent by text"), "Paper bedroom feature wall" BS8 2PX (no checklist),
  "Exterior repaint, front elevation" BS3 1AB (14 items, notes of about 1,500 characters);
  yesterday: one job with a draft, 6 of 9 done. Priya Shah: two today, one submitted this
  morning (awaiting review, 2 before and 2 after placeholder photos). Every other operative: one
  job today. Every existing job gets job checklist items (from its report). Update
  `tests/expected.py` (job count, awaiting-review count +1, recent reports).

## Shared

`operative/status.ts`: `jobStatusLabel(job)` → "To do", "In progress, 6 of 9 done", "Submitted",
"Completed by office", "Cancelled". `hooks/useOperative.ts` `useOperativeJobs` (staleTime 5 min,
refetch on focus and reconnect). Query key `["operative","jobs"]`.

## Mobile

- `app/(app)/index.tsx`: sections "Today" and "Earlier, not finished"; each row: title (wraps
  to 3 lines then truncates), town and postcode, job type label, status word with icon; finished
  rows greyed (contrast still >= 4.5:1). Pull to refresh; "Updated 07:42" from `as_of` in London
  time.
- States: loading skeleton rows (with the last list underneath if cached); empty "No jobs today.
  Pull down to refresh."; error "Couldn't load jobs. Check your signal." with Retry and the last
  list kept; offline "Offline. Showing jobs from 07:42." (persisted cache, design 3.3).
- Every job in the response is written to the persisted cache (`setQueryData` for each
  `["operative","job",id]`), so details work offline (T-003d 9).
- Reconcile: a job with local work that is absent from the list → T-003n "Needs attention"
  (wired in T-003n; here the list simply omits it).
