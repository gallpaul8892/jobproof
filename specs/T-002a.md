## Summary

Adds the single `company_settings` row (created by migration with defaults, never by the seed),
one backend accessor for it, and the public `GET /api/v1/branding`. Also lands the contract
staging mechanism and regenerates the client for the whole epic.

## Patterns

- **Singleton record, not a Singleton class**: the table allows exactly one row (`id = 1`). All
  reads go through `services/settings.py` (`get_company_settings(session)`), which is the one
  settings accessor D1 requires. No caching in the backend: one primary-key read per request is
  cheap, and caching would break "change takes effect on next page load" across ECS tasks.
- No GoF pattern otherwise; plain functions.

## Data

Migration `0002_company_settings` (down_revision `0001`).

**company_settings**
| column | type | notes |
|---|---|---|
| id | smallint pk, default 1 | `CHECK (id = 1)` named `ck_company_settings_singleton`; a second row fails on PK or check (scenario 4) |
| company_name | text not null | `CHECK (char_length(company_name) BETWEEN 1 AND 60 AND company_name = btrim(company_name))` |
| theme_primary, theme_accent, theme_background, theme_surface, theme_text | char(7) not null | each `CHECK (col ~ '^#[0-9A-F]{6}$')` (upper case only; scenario 6) |
| updated_at | timestamptz null | null until the first change |
| updated_by_id | uuid null | **no FK on purpose**, see below |
| updated_by_name | text null | name snapshot at change time |
| created_at | timestamptz not null default now() | |

`CHECK ((updated_at IS NULL) = (updated_by_id IS NULL) AND (updated_by_id IS NULL) = (updated_by_name IS NULL))`.

No FK from `updated_by_id` to `users`: the seed runs `TRUNCATE ... CASCADE` over all tables, and
any FK into `users` would make Postgres truncate `company_settings` too, breaking scenario 1. The
name snapshot is also what the audit trail does (names stay as they were, T-002f scenario 6).
The model does not use `TimestampMixin` (its `updated_at` is non-null with `onupdate`).

Migration upgrade:
1. Create the table.
2. Read `DEFAULT_COMPANY_NAME` from `os.environ` (unset or empty: "Arbour Services"). Strip it;
   fail the migration with a clear message if it is longer than 60 characters or contains a
   control character. This is the only place the env var is read.
3. `INSERT ... ON CONFLICT (id) DO NOTHING` the row with that name and the default theme hex
   codes written literally in the migration (frozen; A3).
Downgrade: drop the table.

Default theme (also in both defaults modules): primary `#1F5130`, accent `#2F5D3A`, background
`#FFFFFF`, surface `#F4F7F2`, text `#1B1F1C`.

Seed: `backend/app/seed/loader.py` excludes `company_settings` from its truncate and insert
lists (an explicit `SEED_PRESERVED_TABLES = {"company_settings"}`), so seeding never changes or
duplicates the row. Since there is no FK into it from a truncated table, CASCADE never reaches it.

## API

`GET /api/v1/branding` (`getBranding`, tag `branding`, `security: []`): 200 `Branding`
`{company_name, theme: {primary, accent, background, surface, text}}`, `additionalProperties:
false`, header `Cache-Control: no-cache`. No error responses besides the global 500. All personas
and anonymous. CORS: covered by the existing allowlist.

## Backend

- `backend/app/branding/defaults.py`: `DEFAULT_COMPANY_NAME = "Arbour Services"` and
  `DEFAULT_THEME` (frozen dataclass `Theme(primary, accent, background, surface, text)`).
  Nothing else in `backend/app` may contain "Arbour" or these hex codes (scenario 5).
- `backend/app/models/settings.py`: `CompanySettings` model with the constraints above.
- `backend/app/services/settings.py`: `get_company_settings(session) -> CompanySettings`
  (raises a 500-level `RuntimeError` if the row is missing: a deployment without the migration
  is broken, not empty) and `get_branding(session) -> schemas.Branding`.
- `backend/app/schemas/settings.py`: `Theme`, `Branding` (Pydantic, `extra="forbid"` not needed
  for responses; the response model only has these fields).
- `backend/app/routers/branding.py`: router with no auth dependency; sets
  `response.headers["Cache-Control"] = "no-cache"`. Registered in `main.py`.
