# Spec T-003k: Photo evidence integrity (timestamp, optional GPS, no editing)

Ticket: [tickets/T-003k-photo-evidence-integrity.md](../tickets/T-003k-photo-evidence-integrity.md).
Package D (after T-003g; may run in parallel with T-003h). Design sections 3.6, 5, 8. Kind:
backend (manager fields, location accepted) + mobile (location capture, clock warning) + web.
P3, P4, P5, Q6.

## Questions and assumptions

- A1. No map; managers see "Location recorded" and, in the enlarged photo, coordinates with
  accuracy as text ("51.4651, -2.5960 (within 12 m)").
- A2. Gallery photos are flagged, not blocked (Q4). Gallery GPS is usually absent on Android 10+
  because we do not request `ACCESS_MEDIA_LOCATION`; the photo then shows "No location".
- A3. Clock warnings are information only; nothing blocks capture or submission.

## Summary

Make the evidence visible to the manager (taken and received times, camera or gallery, location
recorded, clock offset, different day, checklist item) and capture optional location on the
phone.

## Patterns

None. Display rules are one pure function `photoEvidenceFlags` in `shared/src/operative/
evidence.ts`, used by web and mobile.

## Data

None (0011 has the columns).

## API

`PhotoRegistration.location` accepted; manager `ReportPhoto` fields `checklist_item_id`,
`source`, `taken_at_source`, `received_at`, `clock_offset_seconds`, `location`;
`ChecklistItem.cannot_do`, `removed`; `ReportDetail.device_submitted_at`,
`submit_clock_offset_seconds`. Remove `T-003k` from `PENDING_TICKETS`.

## Backend

- Registration stores location (all four parts or none; `source` `device|file`); location is an
  evidence field (immutable).
- Manager report builder emits the new fields; seeded photos: `source camera`,
  `taken_at_source device_clock`, `received_at` null, offsets null, `location` null.
- `location` appears only in manager responses; the operative schema has no location.
- Never log coordinates (test captures logs during a registration with location).

## Shared

`evidence.ts`: `photoEvidenceFlags(photo, jobScheduledStart)` →
`{fromGallery, timeUnknown, clockOffsetText | null ("Phone clock was out by about 3 days"),
differentDay, locationRecorded}`; threshold 300 s; humanised offset (minutes, hours, days,
rounded "about"); London dates. `reportEvidence(report)` for the submit offset. Vitest table.

## Web

`PhotoGallery` cards: stage, "Taken 08:14, received 08:15" (London), "From gallery, taken 14 Oct
17:50" or "Taken time unknown, added 15 Oct 08:20", "Location recorded" / "No location", the
checklist item label, warnings with an icon and text ("Phone clock was out by about 3 days",
"Taken on a different day"). Enlarged view adds coordinates and accuracy. Checklist: "Not done:
reason" for `cannot_do`, per-item photo count and thumbnails, removed items with data under
"Other photos and notes". Report header: "Pressed Submit at 13:58 on the phone" when
`device_submitted_at` differs from `submitted_at` by more than 5 minutes; clock warning if
`submit_clock_offset_seconds` exceeds 300. Manager still has no photo edit control.

## Mobile

- Location (only if permitted, T-003l): at shutter, `getLastKnownPositionAsync({ maxAge:
  120000 })`, else `getCurrentPositionAsync({ accuracy: Balanced })` raced with a 5 s timeout;
  written to the row when it resolves; never delays the next shot.
- Gallery GPS from EXIF → `source: 'file'`; never the phone's current position for a gallery
  photo (scenario 7).
- Clock: the engine stores the offset from `getAppStatus` (midpoint method); if |offset| > 300 s,
  a banner "Your phone's date or time looks wrong. Check your phone settings." and the same
  per-photo note on the operative's own thumbnails once the server reports `clock_offset_seconds`.
- No crop, rotate, filter, markup or replace anywhere (scenario 8; lint rule bans image-editing
  libraries; the manipulator is used only in the upload-copy module).
