# Spec T-003f: Checklist progress, notes and per-item photos (the draft report)

Ticket: [tickets/T-003f-checklist-progress-notes-item-photos.md](../tickets/T-003f-checklist-progress-notes-item-photos.md).
Package C. Design sections 3.3, 3.4, 6, 7. Kind: backend then mobile (sync engine skeleton). P1, P2.

## Questions and assumptions

- A1. Per-item photos optional (P2).
- A2. Office checklist edits have no UI in this epic; scenario 10 is exercised by fixtures that
  add a job item and set `removed_at` on another.
- A3. Two devices editing one draft: last write wins per field (rare, Q13).

## Summary

`PATCH /operative/jobs/{id}/report` (draft save, creates the draft) and the app's local draft
with autosave, plus the **sync engine skeleton** (runner, classifier, retry, triggers, status
line) that T-003g/h extend.

## Patterns

State-based reconciliation with `rev`/`synced_rev` dirty flags (design 3.4), chosen over an
operation log because edits coalesce, repeats are idempotent and there is no ordering to get
wrong. Observer: engine status consumed via `useSyncExternalStore`.

## Data

Server: none (0010). Local: uses `drafts` and `checklist_states` from T-003e's migration.

## API

`saveOperativeDraft` as in the contract (no `sign_off` until T-003o). Remove `T-003f` from
`PENDING_TICKETS`.

## Backend

`services/drafts.py`:
- `ensure_draft(session, job, user, now)`: lock the job row (`FOR UPDATE`); 409 `job_cancelled`
  / `job_closed` (job completed with no submitted report); create the report if none (`state
  draft`, `painter_id = user`, `version 1`, review fields null) and its report items for every
  non-removed job item (same ids); job `scheduled → in_progress`. Used by T-003g and T-003h too.
- `apply_draft_update(report, body)`: 409 `report_submitted` (extension `submitted_at`) if
  submitted; item ids must be unique and belong to the job (removed items allowed), else 422 with
  `loc ["body","checklist",i,"item_id"]`; creates a missing report item for a job item added
  later; `status` → `done`/`cannot_do` booleans; notes and item notes: multi-line rule, blank →
  null, limits 2,000 / 500. No audit event (drafts are invisible to managers).
- Manager PATCH (existing `report_edit.py`): `done: true` also clears `cannot_do` (and the audit
  records the `checklist_done` change as today).
- Returns the full `OperativeJob`.

## Shared

`operative/validation.ts`: `validateItemNote` (500, "Keep it to 500 characters."),
`validateJobNotes` (2,000); `operative/status.ts` progress text reused for the header.

## Web

None (manager display of `cannot_do` is T-003k).

## Mobile

- Item rows: tap toggles done ("1 of 9 done"); item screen `items/[itemId].tsx` with Done, "Can't
  do this" + reason field, note (500), Add photo (camera or gallery with `checklist_item_id` set),
  the item's photos, Move photo to another item (local update + `meta_rev`; server sync in T-003g).
- "Not done" without reason shows as incomplete ("Not done: add a reason").
- Overall job notes (2,000), autosaved on change (debounced 500 ms into SQLite; no Save button).
- Local display = local value when `rev > synced_rev`, else server value. Removed items with local
  data appear under "Other photos and notes".
- **Sync engine skeleton** (`src/sync/`): runner with mutex and re-run flag; triggers (start,
  foreground, reconnect, 2 s after edits, timers, Sync now); `classify.ts` (full table from
  design 3.4, unit tested now even for codes used later); `retry.ts` (5 s, 15 s, 1 min, 5 min,
  15 min, ±20% jitter, `Retry-After`); step 2 of design 3.4 (PATCH dirty drafts); header status
  line component. Background task registration is T-003i.
