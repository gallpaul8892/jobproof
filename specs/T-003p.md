## Questions and assumptions

- A1. Organisation Play developer account owned by the company, Paul as admin; internal testing
  track for Arbour Services' pilot (T3-3).
- A2. No third-party crash vendor: Play Console Android vitals (T3-6).
- A3. **Entry gate**: prod deployed (INFRA-6/7) and the custom domain live (INFRA-8, T3-7).
  Until then only `preview` builds (dev address, demo data) are distributed.

## Summary

A signed AAB on the internal testing track, pointing at production, with listing, data safety
form, privacy policy, permission audit, minimum-version rollback path and recorded device tests.

None.

None. Backend: `MOBILE_MIN_VERSION_ANDROID` set per environment through Terraform (T-003n).

## Mobile

- `eas.json` `production`: AAB, `autoIncrement`, `environment: production` (API address in EAS
  environment variables), no dev client, R8 enabled (SDK 58 default); `android.versionCode`
  remote. `version` from `mobile/package.json` (semver, bumped by the release PR).
- Release build shows no developer menu, no debug banner, no demo-account list (the API does not
  serve it in production anyway).
- Settings shows "App version 1.0.0 (12)" and "Contact the office" (scenario 11).
- Store assets in `mobile/store/`: listing text (British English, name, short and long
  description), privacy policy (generated from `src/privacy/notice.ts`, T-003l), screenshots
  taken from the `screenshots` profile against seeded mock data only, icon 512 px, feature
  graphic, contact email (T3-8).
- Data safety form answers (recorded in `mobile/store/data-safety.md`): collected: photos
  (app functionality), precise location optional (app functionality), name and email (account
  management), other user content (notes); not shared with third parties; encrypted in transit;
  deletion on request via the company; no ads, no analytics.

## Infra / local

- Runbook in `mobile/README.md` (Paul): create the Play app, enable Play App Signing, create the
  Play service account (Google Cloud) and grant it release rights, upload its key to EAS
  credentials (never git), `eas build --profile production`, `eas submit --profile production
  --track internal`, add testers' emails, share the opt-in link.
- Permission audit: after the EAS build, `aapt2 dump permissions` (or `bundletool dump manifest`)
  on the artifact; the allowed list is camera, fine/coarse location, internet, network state,
  wake lock, receive boot completed, foreground-service-less WorkManager entries; anything else
  fails the checklist (scenario 6).
- Target API: confirm Google Play's current target-API requirement for new apps is met by SDK 58
  (targetSdk 36) on the release date; if not, an SDK upgrade ticket comes first.
- Rollback (scenario 10): halt the rollout or promote the previous release in Play Console; raise
  `MOBILE_MIN_VERSION_ANDROID` to retire a faulty version (operatives keep queued work and send it
  after updating).
